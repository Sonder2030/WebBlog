我们很容易把“收藏”误认为“掌握”。链接越来越多，真正需要解决问题时，却依然要重新搜索。

## 从问题出发，而不是从分类出发

过去我总想先设计一套完美的分类体系，再把所有笔记放进去。后来发现，分类应该随着内容自然生长，而不是成为开始记录之前的门槛。

更有效的方式，是从一个具体问题开始：

1. 我遇到了什么问题？
2. 尝试过哪些方法，结果如何？
3. 最后哪一步真正解决了问题？
4. 下次怎样更快复现这个过程？

回答完这四个问题，一篇有用的技术笔记已经有了基本结构。

## 给未来的自己写文档

写笔记时，可以想象读者是六个月后的自己。那时你可能已经忘记环境、参数和上下文，所以关键步骤不能只写结论。

```bash
# 一个清楚的命令，比一句“重新构建即可”更有帮助
npm run build
```

必要的背景、失败尝试和适用条件，往往比最终答案更重要。

## 发布让笔记更完整

公开写作会促使我检查：这个步骤是否遗漏？别人能否理解？信息是否涉及隐私？这种检查本身就是一次复盘。

并不是所有笔记都需要公开。但选择一部分整理发布，可以让私人经验变成能够连接他人的知识。
