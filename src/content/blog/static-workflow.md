一个能够长期维护的博客，不一定需要复杂后台。对我这种更新频率不高、内容以文字为主的人来说，Markdown 加静态托管已经足够。

## 写一篇新文章

首先在内容目录中新建一个 Markdown 文件，在顶部记录标题、摘要、日期和标签，然后开始正文写作。

```yaml
---
title: "文章标题"
description: "一句话说明文章的价值"
pubDate: 2026-11-24
tags: ["随笔"]
---
```

这种格式的好处是内容与网站样式彼此独立。即使未来更换网站框架，文章仍然可以完整带走。

## 在本地检查

发布之前，先在浏览器里检查标题、链接、代码块和手机端排版。生产构建也必须通过：

```bash
npm run check
npm run build
```

构建命令会把整站生成静态文件。此时没有数据库查询，也没有服务器端程序需要运行。

## 用 Git 保存每次变化

确认无误后，再把修改提交到 Git 仓库并推送到 GitHub。自动部署流程会完成构建和发布。

Git 在这里不仅是备份工具，也保留了网站的修改历史。误删内容、调整失败时，都能找回之前的版本。

## 保留简单的权利

未来如果需要评论、搜索或在线后台，可以按实际需求逐步增加。但在那之前，不提前为假设中的需求付出维护成本。

轻量不是功能越少越好，而是每一项功能都恰好服务于当前目标。
